# Sympose Engineering Log: Stylo 0.13.5 → 0.13.6 — Preview Code Blocks Wrap

> **Date:** Sunday, September 13, 2026
> **Topic:** Routine dependency bump closing
> `stylo/docs/requests/2026-09-13_preview-code-blocks-dont-wrap.md`, filed
> earlier the same day after live-verifying that `preview`'s fenced code
> blocks scrolled horizontally on a long line while the in-place canvas
> wrapped the identical line.
> **Participants:** damiro (Lead Architect), Grace (Engineering Partner)
> **Status:** `npm run typecheck` clean, `npm run build` rebuilt
> `sympose/webui/`. No Python touched.

## What shipped

`ui/package.json` / `ui/package-lock.json` `@damiro/stylo` `^0.13.5` →
`^0.13.6`.

`.preview pre` now sets `white-space: var(--stylo-preview-code-white-space,
pre-wrap)` and `overflow-wrap: break-word` instead of falling back to
`<pre>`'s UA default (`pre`, no wrapping) — matching the in-place canvas,
whose wrap was itself never a deliberate per-construct choice
(`EditorView.lineWrapping` applies to the whole CodeMirror document, prose
and fenced code alike). `overflow-x: auto` stays as a safety net for an
unbroken run with no whitespace at all (a long URL or string literal). The
new `--stylo-preview-code-white-space` token defaults to `pre-wrap`, which
is the behavior asked for — no override needed on Sympose's side.

## Verified in the installed package

- `node_modules/@damiro/stylo/package.json` — `0.13.6`.
- `node_modules/@damiro/stylo/dist/styles.css` — confirmed the
  `white-space:var(--stylo-preview-code-white-space,pre-wrap)` rule is
  present on `._preview_* pre`.
- `npm run typecheck` — clean.
- `npm run build` — rebuilt `sympose/webui/` with the new bundle hashes.
