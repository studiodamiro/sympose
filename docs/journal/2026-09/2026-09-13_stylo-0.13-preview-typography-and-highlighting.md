# Sympose Engineering Log: Stylo 0.12.0 → 0.13.0 — Preview Tracks `--stylo-font-size` and Highlights Code

> **Date:** Sunday, September 13, 2026
> **Topic:** stylo (`@damiro/stylo`) shipped 0.13.0 the same day, closing the
> gap the new read/edit toggle (`mode="preview"`, first used in this same
> session) surfaced: Preview's typography didn't track `--stylo-font-size`,
> and its fenced code blocks were never syntax-highlighted at all. Filed as
> `stylo/docs/requests/2026-09-13_preview-typography-and-code-highlighting.md`
> earlier the same day; stylo shipped it same-day too.
> **Participants:** damiro (Lead Architect), Grace (Engineering Partner)
> **Status:** `npm run typecheck` clean, `npm run build` rebuilt
> `sympose/webui/` (no Python touched, so `.venv/bin/pytest` wasn't re-run
> for this bump specifically — see the read/edit-toggle work earlier the
> same day for the last full 398-passing run).

## What shipped

### Version bump

`ui/package.json` `@damiro/stylo` `^0.12.0` → `^0.13.0`. CHANGELOG lists
one `Added` (preview syntax-highlighting) and one `Changed` (preview
typography), both from the request doc below. Neither marked `BREAKING`.

### The gap, and why it was only visible now

Sympose's `index.css` had already bridged `--stylo-font-size: 0.875rem`
and the full `--stylo-syntax-*` color set onto `.stylo` — correctly, and
the in-place canvas had honored both since the original 0.11.0 wiring.
But nothing in Sympose ever exercised stylo's `preview` mode until this
session's read/edit toggle (`markdown-panel.tsx`'s `mode={readOnly ?
"preview" : surface}`), so the fact that `Preview`'s own stylesheet
hardcoded `font-size: 0.9375rem` and never ran a highlighting pass at all
had no way to show up before today.

### Request → fix, same day

Filed as a stylo request doc rather than edited directly (stylo is a
fixed external dependency from a Sympose session — see
`CONTRIBUTING.md`), traced to two root causes:

- `.preview`'s entire `em`-based scale (headings, lists, code, table
  cells) was relative to a hardcoded base font-size, not
  `var(--stylo-font-size)` — one property change cascades the whole scale.
- `Preview.tsx`'s remark/rehype pipeline had no highlighting step, and the
  `--stylo-syntax-*` tokens were wired only into the editor's
  `syntaxHighlighting(styloHighlightStyle)` CodeMirror extension — a
  live-editor-only mechanism. 0.13.0 reuses the same `styloHighlightStyle`
  mapping and the same Lezer grammars `codeLanguages` already loads,
  walked headlessly via `@lezer/highlight`'s tree APIs, so a code block
  now looks identical read or edited by construction — no second
  highlighter, no separate color mapping to keep in sync by hand.

Sympose needed no prop changes to pick this up: `markdown-panel.tsx`
already passes `codeLanguages={CODE_LANGUAGES}` to `<Stylo>`
unconditionally (used previously only by `source`/`in-place`/`split`),
and that's the only opt-in 0.13.0's preview highlighting needs.

### Verified in the installed package

Before rebuilding, confirmed the actual shipped diff rather than trusting
the CHANGELOG alone:

- `node_modules/@damiro/stylo/dist/styles.css` — `.preview`'s rule now
  reads `font-size:var(--stylo-font-size,.9375rem)`.
- `node_modules/@damiro/stylo/dist/Preview-*.js` now imports
  `highlightCode` from the shared highlight module.

`Preview`'s own chunk grew modestly (177.00 kB → 178.21 kB gzipped:
53.21 → 53.76 kB) — the `@lezer/highlight` tree-walking weight the
request doc's trade-offs section flagged, not a full CodeMirror
`EditorView`.
