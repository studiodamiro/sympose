# Sympose Engineering Log: Stylo 0.13.1 → 0.13.5 — Table-Cell `readOnly`, Preview/In-Place Rhythm Consolidation, Table-Exit Caret Fix

> **Date:** Sunday, September 13, 2026
> **Topic:** Routine dependency bump — three stylo patch releases (0.13.3,
> 0.13.4, 0.13.5) landed same-day on top of the 0.13.1 already in use, none
> of them touching a prop or behavior Sympose exercises directly. Pulled all
> three in one bump rather than three.
> **Participants:** damiro (Lead Architect), Grace (Engineering Partner)
> **Status:** `npm run typecheck` clean, `npm run build` rebuilt
> `sympose/webui/`. No Python touched, so `.venv/bin/pytest` wasn't re-run
> for this bump specifically.

## What shipped

`ui/package.json` / `ui/package-lock.json` `@damiro/stylo` `^0.13.1` →
`^0.13.5`.

### 0.13.3 — editable-table exit caret

Exiting an editable table (`inPlace={{ table: "cells" }}`) downward via
arrow keys could land the caret above the table instead of below it when
the table was the last block in the document; `insertTable` also left no
blank line after a table landing at the end of a document. Sympose exposes
`table: "cells"` as a user-facing "Table editing" preference (Settings ›
Markdown editor, `editor-preferences-section.tsx`) — real fix for anyone
who's switched it on, not just a latent one.

### 0.13.4 — preview/in-place rhythm consolidation

`preview` and the in-place canvas each hard-coded their own copy of the
same six rhythm values (heading sizes, callout radius/padding, list-item
spacing), and three had drifted apart — most visibly, `preview` had no
`font-size` at all for h5/h6, silently falling back to the browser default
instead of matching in-place's `0.9em`. Both surfaces now read shared
internal `--stylo-rhythm-*` custom properties instead of authoring their
own copy. Purely internal (not part of the documented styling-tokens
surface) — Sympose doesn't override these, so `mode="preview"` (the
read/edit toggle's read side, per `markdown-panel.tsx`'s doc comment) picks
up more consistent heading/list/callout spacing with no code change here.

### 0.13.5 — `readOnly` reaches editable table cells

`inPlace={{ table: "cells" }}` renders cells as a native `contenteditable`
region entirely outside CodeMirror's `readOnly` control — the same class of
gap as the context-menu/selection-bar fix in 0.13.1, one layer deeper.
`readOnly` now falls the canvas back to the plain (non-editable) table
rendering instead. No effect on Sympose either way, but not for the reason
0.13.3 doesn't apply: the read/edit toggle never sets in-place `readOnly`
at all regardless of `tableEditing` — it swaps to `mode="preview"` instead
(`markdown-panel.tsx`'s file doc comment, still accurate: the link-click
gate the comment cites as the decisive reason is untouched by any of these
three releases). This fix matters the day that comment's workaround is
ever revisited.

### What this bump does *not* close

`stylo/docs/requests/2026-09-13_inplace-preview-shared-style-source.md`
asked for two things, ranked by value. Ask #2 ("one shared values module
for the constructs that aren't content-dependent") is what 0.13.4 above
delivers. Ask #1 — the one the request itself calls "the only one that
actually reaches the vertical-rhythm problem" — is still open: in-place's
gap before a heading/callout is a function of how many blank source lines
precede it (a real `.cm-line` at the shared line-height), while preview's
is a fixed CSS margin. For a document with no blank line before a heading,
the two surfaces will still visibly disagree, and no CSS Sympose writes
from `index.css` can fix that — it has to change inside stylo's in-place
renderer (normalizing blank-line runs into a fixed decorative gap, the way
Obsidian's own live preview does). Don't read this bump as closing the
preview/in-place parity problem — it closes one contributing mechanism,
not the deepest one.
